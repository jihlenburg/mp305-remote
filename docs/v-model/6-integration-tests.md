# 6. Integration test specification (IT)

Status: approved (G3, user, 2026-09-30; IT-011, IT-026 and IT-017 changes approved 2026-09-30, revisions 3 and 4)

Integration tests verify the architecture items in
[3-architecture.md](3-architecture.md). They run without hardware against
`transport::mock` on a paused Tokio clock unless the entry says otherwise,
live in `crates/<crate>/tests/it_*.rs` (Rust) or `tests/integration/`
(Python), and each test names its IT ID in its doc comment
(`/// Test: IT-020`) or marker (`@pytest.mark.spec("IT-040")`). An entry
whose method is inspection names the artefact to inspect and the
verification record that holds the result
(`docs/v-model/records/YYYY-MM-DD-integration-<scope>.md`).

The mock transport is scripted: a test gives it the replies to send for each
request, frames to inject at given clock times, delays, and errors, and it
records every frame the system sent. Byte-exact fixtures come from
[docs/research/protocol.md](../research/protocol.md), the captures under
`docs/research/captures/` (cited by file name and event timestamp in the
test), and the emulator vectors of the firmware reconstruction
(`docs/research/firmware/v51/independent/notes/commands.md`, section 11).
The emulator vectors are payload-level with the bridge's route suffix; the
HID-framed fixtures below are derived from them by hand following
protocol.md 2.2 and say so in the test.

Fixtures used by several entries:

- `C3_CAPTURE`: the 38-byte AF01 notification of `2026-09-29T193614`
  (`31 c3 ...`, setpoints 1300 and 1000, output 0, percentage 90).
- `E1_BLE`: the 17-byte AF02 reply of the same capture
  (`e1 01 06 00 28 4d 50 33 30 35 42 00 00 02 00 02 00`).
- `E1_USB`: the 31-byte layout of protocol.md 4.4 with the version
  `01 06 00 33` and eight placeholder bootloader bytes; never captured
  (TBD-010), so the test states that it is a constructed fixture.
- `C8_170`: the HID stream of a `0xC8` with `remoteCon = 1`, 1.70 V (raw
  170 = `0xAA`, sent as `AA AA`), 0.100 A, other fields from `C3_CAPTURE`:
  `AA 12 0C C8 01 AA AA 00 64 00 00 00 00 00 00 00 <sum>`, sum computed by
  the test from the unstuffed bytes.
