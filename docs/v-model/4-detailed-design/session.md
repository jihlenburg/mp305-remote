# DD: session module of `mp305-core`

Status: approved (G4 session, user, 2026-10-01, revision 3)

Refines AR-025 to AR-030 of [3-architecture.md](../3-architecture.md)
(approved at G3), takes its clock rule from AR-003, its numbers from
AR-014 and its error variants from AR-050. Device facts cite
[docs/research/device-model.md](../../research/device-model.md) with their
evidence labels (code, hardware, inferred). The module is the device API
the two products use. It owns one `link::Link` at a time, the link state
machine (connect, bind, ready), the remote-control state machine, the
building and guarding of every `0xC8`, the readings and events the
products see, the unclean-exit marker, link loss and reconnection, and
the one-connection-per-identifier registry. It builds frames only through
`protocol::ops` and sends them only through `link`, so the allowlist and
the one-request rule hold here by construction. Coverage target 85 %
(ADR-0008, "rest of `mp305-core`"); nothing here needs a device.
Revision 2 resolves the independent review of revision 1 and revision 3
its second pass (LOGBOOK, "Session design review").

Rust module tree: `mp305_core::session` with the submodules `state` (pure:
the two state machines, freshness, the rejection reason, the setpoint
comparison), `texts` (the user-facing constants and the RFC 3339
formatter), `task` (the loop that owns the link), `doubles` (under
`cfg(any(test, feature = "mock"))`: `MockConnector`, `MemoryMarkers`) and,
under `cfg(test)`, `tests`. The public handle `Session`, the
`SessionEvents` receiver, the event and option types and the two injection
traits live in `session/mod.rs`; the new error variants in `error.rs`; the
shared test fixtures in `protocol::fixtures` (section 9, decision 2).
Every source file starts with `//! Implements: DD-SESS-nnn, ...`.

What the module takes from outside, so that it depends on no module whose
design is not yet approved: a `Connector` (how an identifier becomes a
`Guarded<AnyTransport>`; `discovery` implements it for real devices and
`doubles::MockConnector` implements it over `transport::mock`), a `Markers`
store (the unclean-exit marker; `store` implements it, `doubles::
MemoryMarkers` is the test double) and the `HostId`
(`protocol::ops::bind::HostId`, which `store` keeps and the product
passes). Terms: "the reading" is the latest `RawReading` with its arrival
stamp; `last_c9_at` is the arrival stamp of the last `0xC9` the session
handled, from an `Outcome::Reply` or from a `Pending`; "fresh" means the
reading arrived after `last_c9_at` and at most `timing::REPLY` ago on the
Tokio clock; "DC mode" means `live_mode == LiveMode::Dc` in the reading;
"the generation" is a counter the task increments at the start of every
connection attempt (the first connection and each reconnection attempt);
the handle stamps every command with the value current when the call is
made; hex is lowercase two-digit.

## 2. The link state machine

| ID | Design item | Refines | Status | Rationale |
|---|---|---|---|---|
| DD-SESS-010 | The connect flow, run inside the task loop (DD-SESS-030) once at start and once per reconnection attempt, each with a new generation. State `Connecting` (or `Reconnecting`, which stays for the whole attempt): `connector.connect(identifier)` is awaited as a step; an error ends the flow with that error. On success `connected_at = now`, `Link::start(guard, connected_at)` gives the link and its events, the kind is read from the link's description, state `Connected` (not during a reconnection attempt). Then over `Kind::Ble` the bind (DD-SESS-011); over `Kind::Hid` no bind: `info::request()` is sent and its `0xE1` makes the state `Allowed` (DD-SESS-012). Then the first reading (DD-SESS-012), then `Ready`. Between `Connected` and `Allowed` nothing but the bind frames (Bluetooth) or the one `0xE0` (USB) is sent, and polling is off. A control command that arrives before `Ready` on the first connection is answered `Error::NotReady` without being sent; during a reconnection attempt it is answered `Error::LinkLost` (DD-SESS-030). A loss (`DeviceEvent::LinkLost`, or `Events` ending) during the flow ends it with `Error::LinkLost { text }`, state `Lost`, and emits `LinkLost { text }` with `texts::lost_while_connecting(reason)` ("The link to the supply was lost while connecting: <reason>."), since no grant and no output statement apply yet. | AR-026 | approved | device-model.md 4.1 (code, hardware) and 4.2 (code, TBD-004): the bind is the Bluetooth gate, USB has none, and SR-011 makes the `0xE1` the USB "allowed" signal. |
| DD-SESS-011 | The bind, state `Binding`. First `link.request(bind::request(&host_id, true))` (immediate; the Bluetooth chip answers from its memory within one round trip). `19 00`: state `Allowed`, event `BindResult { recognised: true }`. `19 FF`: `link.request(bind::request(&host_id, false))`, which comes back as `Outcome::Deferred(pending)` (the 30 s bound from `connected_at`, DD-LINK-010); event `Prompt { ConfirmConnection, 30, texts::CONFIRM_CONNECTION }`; then await `pending` as a step. `19 00`: `Allowed`, `BindResult { recognised: false }`. `19 FF`, a `0x19` with any other status (`Reason::Value` from `bind::parse`) or a malformed `0x19` (a length error): state `Denied`, `link.close()` awaited, the flow ends with `Error::ConnectionDenied` (SR-010: anything but `19 00` is a deny). `Error::Timeout` from the pending: the link is closed and the flow ends with `Error::Timeout { opcode: 0x18, after: timing::BIND }`. `Error::Timeout` from the fast bind (its own 1 s window): the link is closed and the flow ends with `Error::Timeout { opcode: 0x18, after: timing::REPLY }`; the chip answers a fast bind locally within one round trip (device-model.md 3), so a missing answer means the link is not usable, and a retry would only run into the link's loss rule (DD-LINK-023). `Error::LinkLost`: as DD-SESS-010 says. | DD-SESS-012 | Ready. Then, on the first connection only, the marker: if `markers.present(identifier)` returns a time, event `UncleanExitWarning { since, text }` is delivered (SR-046); on a reconnection the marker is this session's own and the check is skipped. Then `link.set_polling(true)`, state `Ready`, `ReadyState::Ready(info)`. `ready()` therefore resolves after the first reading, the marker check and the polling switch, in that order. Over USB the `0xE1` of DD-SESS-010 is this info request, so it is not sent twice. | AR-026, AR-025 | approved | SR-012: info and one reading before any control; UR-030: the warning before any control action. ## 4. Control commands

| ID | Design item | Refines | Status | Rationale |
|---|---|---|---|---|
| DD-SESS-030 | The task is one loop over a `biased` `tokio::select!` with these arms in order: (1) the link's `Events` (`next()`, enabled only while a link exists and the stream has not ended; readings, device frames, late replies, loss); (2) the priority channel (`Close`, `OutputOff`), always enabled; (3) the step in progress, when there is one; (4) the reconnect timer, when scheduled; (5) the command channel, enabled whenever no control-command step is in progress (the connect flow, a reconnection attempt and the close sequence do not disable it), so that a command is answered at once by the link state: only `Ready` accepts it; every other state answers as listed below without a step. A "step" is one awaited future held in an enum `Step { Connect(BoxFuture), Request(Requested, ..), Pending(Pending, ..), Sleep(..) }` with its continuation data; `Requested` and `Pending` are `Unpin`, so the arm polls `&mut` the future. The connect flow, the bind wait, every control command and the close sequence run as steps, so readings, queries, `NotReady` answers and the priority channel are served during the 30 s bind wait, the 70 s remote prompt and every request. A control command runs as steps inside the task, never on the caller's task. Before each step of a command (a poll, a request, a write) the task checks the caller's `oneshot` and cancels the command if the caller is gone (DD-SESS-003). Control commands in `LinkState::Connecting`, `Connected`, `Binding`, `Allowed` get `Error::NotReady`; in `Lost` and `Reconnecting` `Error::LinkLost { text }` with the last loss text; in `Denied` `Error::ConnectionDenied`; in `Closed` `Error::LinkLost { text: "closed by the host" }`; a command stamped with a generation older than the current one gets `Error::LinkLost` (DD-SESS-050), which also covers a command made during `Reconnecting`. The `output_off` sequence and the close sequence count as control-command steps and disable arm (5) while they run; commands wait and run after an output-off. From the moment a close starts (a closing flag), every command is answered `Error::LinkLost { text: "closed by the host" }`, including those that arrive while close step (b) still runs in `Ready`. Once `Events::next` returned `None` the arm is disabled. ## 8. The design as flows

Bluetooth connect, first setpoint, an output-off behind a queued setpoint,
and a loss, as the task runs them:

```
connect(connector, id, host_id, markers, options) -> (Session, SessionEvents)
task: connector.connect(id) -> Guarded -> Link::start
      bind fast  -> 19 00: Allowed, BindResult{true}
                 -> 19 FF: bind prompt (deferred), Prompt(ConfirmConnection, 30)
                           19 00: Allowed, BindResult{false}
                           other: Denied, link closed, ready() = Err(ConnectionDenied)
                           timeout/loss: link closed, ready() = Err(Timeout | LinkLost)
      info 0xE0 -> Info; 0xC2 -> first Reading; UncleanExitWarning if a marker exists
      polling on; Ready; ready() = Ok(Info)
set_voltage(1.7): range ok; reading fresh? else 0xC2; DC? remote None ->
      0xC8 rc=2 (deferred), RemoteControl(Requested), Prompt(AllowRemoteControl, 70)
      readings keep flowing; 0xC9 0 -> Granted (last_c9_at moves)
      0xC2 (reading now stale); 0xC8 rc=1 voltage=170, rest copied -> 0xC9 0 -> Ok
set_current_limit(0.1) queued; output_off() arrives on the priority channel:
      the queued call fails Cancelled; 0xC8 rc=1 output=0 (urgent) -> 0xC9 0;
      0xC2; SetpointsChanged if a setpoint differs; markers.clear
link lost: RemoteControl(Lost), LinkLost(text), ready() = Err(LinkLost);
      reconnect off: stays Lost
```
