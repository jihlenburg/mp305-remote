# DD: the desktop app (`mp305-app`)

Status: approved (G4 app, user, 2026-10-01, revision 2; revision 3 approved 2026-10-02); revision 4 drafted, approval pending

Refines AR-041 of [3-architecture.md](../3-architecture.md) (approved at
G3) and the app parts of AR-001, AR-003, AR-004, AR-033, AR-034 and AR-042.
The app is a window on `mp305_core::session`. A worker task on a Tokio
runtime owns the session and does all device I/O; a recorder thread does
all file writes; the UI thread holds a `Model` of what to show, drains the
worker's events once per frame, draws, and turns clicks into commands. The
rules of the device (when a command may be sent, what a `0xC8` carries,
what a loss means) are the core's; the app adds none and bypasses none.
Every rule about what a click may send, when the window may close and what
the user is told lives in tested modules (`model`, `fields`, `texts`,
`actions`, `app`, `worker`, `shell`, `recording`); `ui/` holds the drawing
functions and the eframe glue, which decide nothing. Coverage target 80 %
of lines for the non-rendering logic (ADR-0008); `ui/` and `main.rs` are
excluded (section 8, decision 9). Revision 2 resolves the review of
revision 1 (issues A1 to A33).

Rust module tree (`crates/mp305-app/src/`): `lib.rs` (crate root, `pub mod`
for every module below, so that IT-041 reaches `worker`, `model` and
`chart`); `worker.rs` (the worker task, its commands, events and session
slot; the only file that names `session::Session`, `discovery::Discovery`
or `store::Store`); `shell.rs` (the runtime and the worker's life cycle);
`recording.rs` (the recorder thread); `paths.rs` (the state and recording
directories); `model.rs` (the non-drawing state, `apply`, the
enabled-state and display methods); `chart.rs` (the bounded chart buffer);
`fields.rs` (the setpoint and limit fields); `texts.rs` (the texts of
DD-APP-014); `actions.rs` (what the UI can ask for, its translation into
commands, the close step); `app.rs` (`AppCore`: the frame logic and the
action dispatch); `frametime.rs` (the frame-time and reading-delay notes);
`logging.rs` (the logger set-up); `ui/` (`mod.rs` with the `eframe::App`
glue, `launch.rs`, `screens.rs`, `status.rs`, `connect.rs`, `panel.rs`,
`chart.rs`, `dialogs.rs`); `main.rs` (calls `mp305_app::ui::launch`).
Every source file starts with `//! Implements: DD-APP-nnn`. The
dependencies are section 8, decision 1; the minimum Rust version is
decision 10.

Terms: "the worker" is the task of DD-APP-001; "a command" is a
`worker::Command`; "an event" is a `worker::AppEvent` or a
`worker::UiReading`; "an action" is an `actions::UiAction`; "sid" is the
number the worker gives each connection attempt (DD-APP-005); "the
reading" is the model's latest `TimedReading`; "DC mode" means
`live_mode == LiveMode::Dc` in the reading; "a session call" is a call of
a session control method or of `close`; "first-polled" means the worker
polled the call's future once inside its loop (DD-APP-003); `Err(App, t)`
is short for `Err(ErrorText { kind: ErrorKind::App, text: t })` and
`Err(K, t)` likewise for the kind `K`; `timing::REPLY` is the core's
reply bound, 1 s; "a clock" is `actions::Clock { now: Instant, wall:
SystemTime }`, read once per call by `Clock::now()`. Every `Instant` in
this document is `tokio::time::Instant` (the session's stamps are); on the
UI thread, outside the runtime, it reads the system clock. Time arithmetic
uses `checked_add`, `checked_duration_since` and
`saturating_duration_since` only.

## 7. Phases at a glance

| Phase | Screen | Entered on | Left on | Window close request |
|---|---|---|---|---|
| `Idle` | connection | start, `ScanResult`, `ConnectFailed`, `Disconnected`, `Fatal`, a refused `Connect` or `Reconnect` | `Scan`, `Connect` | closes at once |
| `Scanning` | connection | `Scan` | `ScanResult` | closes at once (the scan is dropped at exit) |
| `Connecting` | connection, with the bind prompt and `Cancel` | `Connect`, `Reconnect` | `Ready`, `ConnectFailed`, a refused `Connect` or `Reconnect`, `Disconnect` | no question; closes after the session is closed |
| `Connected` | main | `Ready`, `Reconnected` | `LinkLost`, `Disconnect` (after the question when the output may be on) | the question when the output may be on, else as `Disconnect` |
| `Lost` | main, controls off, the loss banner, `Reconnect` | `LinkLost` | `Reconnected`, `Reconnect`, `Disconnect` | no question (the banner says the output is in its last state); closes after the session is closed |
| `Closing` | main, with `closing_line()` | a `Disconnect` command | `Disconnected`, `ConnectFailed` | waits; once 5 s have passed after the `Disconnect`, counted only while no prompt is open, it closes (no switch-off asked) or offers `Close anyway` (switch-off asked) |

The window close with the output on, as the parts run it:

```
Connected, reading shows output on
  close_step: CancelClose, question (Window), Minimized(false) + Focus; bound not running
  user: Switch off -> Disconnect { output_off: true }, phase Closing, bound starts
  worker: close(true) first-polled; session: output-off, poll, release, link close
  worker: drain events; Disconnected { text, off_requested: true, output_on }
  model: output_on == Some(false) -> Idle (an error text as an Error banner); close_step: CloseNow
         otherwise -> Idle with the OffFailed banner; the window stays open
  eframe: close request (committed, passes) -> on_exit -> AppCore::on_exit -> Shell::shutdown(3 s)
  Closing past 5 s with no prompt open: Close anyway offered (switch-off asked) or CloseNow (not asked)
```

## 9. Unit test specification

Tests live next to the code under `#[cfg(test)]` (`chart.rs`, `fields.rs`,
`model.rs`, `texts.rs`, `actions.rs`, `app.rs`, `frametime.rs`,
`logging.rs`, `paths.rs`, `recording.rs`, `shell.rs`, `worker.rs` for the
pure `on_events_end`) and in `crates/mp305-app/src/worker_tests.rs`, a
submodule of `worker` compiled under `cfg(test)`. The crate's
dev-dependencies are `mp305-core` with the `mock` feature (for
`session::doubles::{MockConnector, MemoryMarkers}`, `transport::mock` and
`protocol::fixtures`), `tokio` with `test-util`, and `tempfile`. Worker
tests run on a paused Tokio clock (`#[tokio::test(start_paused = true)]`,
current thread) with `worker::run` spawned, unless the entry says
otherwise. The test script, built in `worker_tests.rs` with the public
mock API like the default script of the session tests (session DD,
section 10): Bluetooth; `0x18` answered `19 00` after 50 ms; `0xE0`
answered `E1_BLE` after 100 ms; `0xC2` answered `C3_CAPTURE` (DC mode,
output 0, no faults, setpoints 1300 and 1000) after 130 ms, forever;
`0xC8` answered `0xC9 00` after 100 ms, forever; `MemoryMarkers` empty;
limits 30 V and 5 A; reconnect off; the host ID sixteen bytes `01`; the
identifier the UT ID with a letter per case. On it `Ready` comes 280 ms
after `Connect` and readings follow every 230 ms (510 ms, 740 ms, and so
on); a `RequestRemoteControl` sent at `Ready` is granted 100 ms later, and
"granted" in an entry means after that request's `Done` with `Ok`. A
`0xC2` reply variant is `fixtures::c3_with(output, model, chargeError,
set_voltage, set_current)`. Model tests use `r(output, model, faults,
set_v, set_a, at)`: a `TimedReading` with that `at`, `wall`
2026-10-01T10:00:00Z plus `at` minus `t0`, and the reading of
`c3_with(output, model, faults, set_v, set_a)` through `telemetry::parse`
and `Reading::from_raw`; `faults` is the `chargeError` value, whose bit
n is fault n of DD-PROTO-027 (32 is bit 5, over current). `t0` is a
fixed `Instant`, and times in the entries are offsets from it. `A` is a
`Found` with kind `Ble`, identifier `A`, name `MP305B` and unit `ABC`
(`Display` `ble A MP305B (unit ABC)`); `B` one with kind `Hid` and
identifier `B`; `F` the `Found` a scripted scanner returns; `info` is
`E1_BLE` parsed and `s` a `Settings` value. `T`, `L`, `M`, `E`, `p` and
`x` stand for fixed strings the test chooses (an unclean-exit text, a
loss text, a scan message, a close error, a path, an error text) where
the entry does not give them. "The connected model" is a `Model` after
`Select("A")`, `Connect` (id 1), `Connecting { 1, "A" }`, `Done { 1,
Connect, Ok }`, `UiReading { 1, r(0, 0, 0, 1300, 1000, 0 s) }` and
`Ready { 1, info, Some(that reading), Some(Ble) }`, with no limits and
remote `None`.
