## Deviations from the design

- Four gaps the implementer reported, resolved in the code and recorded as
  revision 3 of the DD (approved 2026-10-01): DD-LINK-020, 030 and 031 said
  "queue is empty" where DD-LINK-022 and 042 let the poll and keepalive run
  while a head waits; the deadline list had no wake-up for a `0xC2` waiting
  only on the 100 ms pause with polling off, which would have stalled the
  link; DD-LINK-021 did not say that `late_replies` grows for a reply to a
  dropped `Pending`, which UT-LINK-015 expected; `output_off` did not say
  what a `0xC8` of the wrong length gets (`Reason::BadLength`).
- Choices the DD left open, recorded in revision 3 where they touch an
  item: `last_sent_at` moves only on a write that went out; a dropped
  `Link` resolves waiting futures with "closed by the host"; `close()` on
  a lost link returns `Ok(())`; the expectation log lines use the request
  opcode; a connection-bound deferred request past its deadline is
  resolved with `Timeout` when the send step reaches it and logs nothing.
- The queue has per-deque accessors beyond DD-LINK-011 (`urgent_head`,
  `normal_head`, `pop_urgent`, `pop_normal`) because the send step weighs
  the two heads separately; `pop_front`, `len` and `is_empty` are kept for
  the tests with an allow on the unused-code lint.
- UT-LINK-009 case 2 feeds the frame at 1.001 s (Tokio's timers have 1 ms
  resolution), stamped 1 s + 1 ns as specified.
- The `Stub` gained a cloneable `StubHandle` (the failure switch and the
  close counter stay reachable after the stub moved into a `Guarded`), and
  `test_log` gained per-thread records with `lines_here`, so that parallel
  tests do not see each other's lines. Neither has a DD item; the transport
  DD's section 7 preamble (revision 5) describes the `Stub` additions.
