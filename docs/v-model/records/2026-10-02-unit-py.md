## Deviations and open points

1. Two tests go beyond their entries' listed cases: an exception that is
   not an `Mp305Error` raised by `close()` (tagged UT-PY-015), and an
   interrupt while the exit hook logs its warning (tagged UT-PY-024).
   Revision 4, drafted and pending approval, adds them as UT-PY-015 (g)
   and UT-PY-024 (l), and states in DD-PY-043 that `__exit__` lets such
   an exception propagate with the original as its `__context__`.
2. UT-PY-024 (d): under full load the child reached its end 0.06 to
   0.33 s after the second Ctrl-C, against the entry's 0.5 s. The spread
   comes from an exit hook that stops and joins the log thread, which is
   beyond DD-PY-006. Revision 4 states the hook and allows 1 s for the
   exit while the "abandoned" record keeps its 0.5 s.
3. One test failed once in nine suite runs of the revision 2 code, under
   an instrumented build and load. The agent reproduced it as UT-PY-009
   (a): the test read the frame records right after `connect` returned,
   and a call can return before its records are delivered. Five tests now
   poll for at most 1 to 2 s instead of reading at once (UT-PY-009 (a)
   and (d), UT-PY-008 (c), UT-PY-019 (d)) or wait before clearing
   (UT-PY-009 (b)); UT-PY-012 (c)'s "at once" is 1 s instead of 0.5 s.
   No bound that an entry gives was changed. Four further loaded runs by
   the agent and three runs in the main session were clean.
4. Fixed during the work: `close()` could hang when its flush request
   met the end of the event forwarder; `Feed::flush` now also returns
   when the feed has ended (a Rust test holds it).
5. Smaller readings of the design, to be stated in it or accepted:
   `wait_safety(dispatch)` accepts `dispatch` and never calls it, since
   it has no feed (DD-PY-008); dispatch stops at the newest event noted
   when it starts (DD-PY-003, DD-PY-044); no "fewer readings" warning
   while reconnecting (DD-PY-050); `setpoint_range_text` accepts only the
   five field names the core uses (DD-PY-033); the stub declares
   `__all__` and stubtest uses an allowlist for the tuple aliases that
   exist only in the stub (DD-PY-061); in UT-PY-024 (a) the child also
   sets its root logger to INFO, since `set_log_level` sets only
   `mp305.core` (DD-PY-006).
6. Not exercised, since they need a supply: `_native.discover` after its
   checks, `Session.connect` with the real `Discovery` and `Store`, and
   the default state directory as `connect` uses it. They count inside
   the 80 % (ADR-0015).
7. The wheel workflow `.github/workflows/wheels.yml` was written and
   never run. It runs only on manual dispatch and on tags `v*`. Only
   macOS arm64 was built and tested here; Linux and Windows wheels are
   unverified.
8. The reviewer's finding that no test held the exit wait for an
   interrupted `output_off()` is closed by UT-PY-024 (a), (i) and (j).
   The path of the first major finding (an interrupt in the very slice
   in which a failing output-off completes) is closed by the rule that a
   failure is always logged at ERROR, held by UT-PY-024 (k) and a Rust
   test of the rule; the race itself is not driven by a test.
